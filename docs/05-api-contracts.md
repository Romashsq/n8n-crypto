# 05. API contracts

> **Frozen contract.** Change it only through the process in [09-workstreams.md#contract-changes](09-workstreams.md#contract-changes) and log the change in [CHANGELOG.md](CHANGELOG.md). Paths are versioned (`/v1/`). A breaking change gets a new version path.

## 0. Conventions

- JSON in UTF-8. **Field names are `snake_case`** everywhere, matching the database columns.
- Timestamps are ISO 8601 UTC strings (`2026-10-07T12:04:00Z`). The one exception is candle times, which are **unix seconds**, the format `lightweight-charts` expects.
- IDs are UUID v4. `request_id` is generated by the web app, one per user message.
- Numbers are JSON numbers, never strings. Percentages are in percent units (`1.24` means +1.24%). Weights are fractions (`0.41`).
- Error body everywhere: `{ "error": { "code": "VALIDATION_ERROR", "message": "Human-readable text", "details": {} } }`.

| Error code | HTTP | Meaning |
|---|---|---|
| `UNAUTHORIZED` | 401 | No session (web) or missing/invalid `X-Aura-Key` (n8n) |
| `FORBIDDEN` | 403 | Resource belongs to another user |
| `VALIDATION_ERROR` | 400 | Bad input; `details` lists fields |
| `NOT_FOUND` | 404 | Unknown chat, message or user |
| `RATE_LIMITED` | 429 | More than 10 sends per minute per user |
| `AGENT_UNAVAILABLE` | 502 | n8n unreachable or returned 5xx |
| `UPSTREAM_ERROR` | 502 | A market data provider failed |
| `TIMEOUT` | 504 | Upstream exceeded its timeout |
| `INTERNAL` | 500 | Anything else |

## 1. Shared TypeScript types

The Web App session copies these into `apps/web/src/lib/contracts.ts`. n8n Code nodes follow the same shapes.

```ts
export type Workspace = 'main' | 'trading' | 'horizon' | 'portfolio';
export type AssetClass = 'crypto' | 'stock' | 'etf' | 'index' | 'gold' | 'cash';
export type ComposerAssetClass = 'crypto' | 'stock' | 'index' | 'gold'; // the composer dropdown
export type Timeframe = '1m' | '5m' | '15m' | '1h' | '4h' | '1d' | '1w';
export type AgentMode = 'chat' | 'portfolio_review' | 'daily_review';
export type MessageRole = 'user' | 'assistant';
export type MessageStatus = 'complete' | 'error';
export type RunStatus = 'queued' | 'running' | 'completed' | 'refused' | 'failed';
export type ArtifactKind = 'report' | 'thesis' | 'portfolio_review' | 'note';
export type RiskProfile = 'conservative' | 'balanced' | 'aggressive';

export interface ChatContext {
  asset_class?: ComposerAssetClass | null;
  symbol?: string | null;      // canonical symbol: BTCUSDT, NVDA, SPX, XAUUSD (docs/04 §3)
  timeframe?: Timeframe | null;
}

export interface SourceRef {
  name: string;                // "Binance", "SEC EDGAR", "FRED"
  detail: string;              // "BTCUSDT 1h klines (300)", "NVDA 10-K FY2026"
  as_of: string | null;        // ISO UTC of the data, not of the request
  url: string | null;
}

export interface ChartRef {
  symbol: string;              // canonical symbol
  asset_class: Exclude<AssetClass, 'cash'>;
  timeframe: Timeframe;
}

export interface AssistantMetadata {
  agent: Workspace;
  mode: AgentMode;
  model: string | null;
  on_topic: boolean;
  suggested_workspace: Workspace | null;
  chart: ChartRef | null;
  sources: SourceRef[];
  artifact_id: string | null;
  latency_ms: number | null;
  error_code: AssistantErrorCode | null;   // set only when message.status = 'error'
}

export type AssistantErrorCode =
  | 'AGENT_FAILED' | 'AGENT_TIMEOUT' | 'DATA_UNAVAILABLE' | 'BUDGET_EXCEEDED' | 'RATE_LIMITED';
```

**Fixed texts** (exact strings, used by the gateway):

| Case | `messages.status` | Text |
|---|---|---|
| Off-topic refusal | `complete` (`metadata.on_topic = false`) | `I'm Aura, your financial intelligence assistant. I can only help with markets, trading, long-term investing, macroeconomics and your portfolio. Please ask me something on one of those topics.` |
| `AGENT_FAILED` | `error` | `I couldn't finish this answer because of an internal error. Please retry in a moment.` |
| `AGENT_TIMEOUT` | `error` | `This took too long and was stopped. Please retry, or ask a narrower question.` |
| `BUDGET_EXCEEDED` | `error` | `You've reached this month's message limit.` |

## 2. Browser ↔ Supabase (direct, protected by RLS)

The browser uses `@supabase/supabase-js` with the publishable key and the user's session. Tables and policies are in [06-database.md](06-database.md).

| Operation | Query (supabase-js) |
|---|---|
| List sidebar chats | `from('chats').select('id,workspace,kind,title,is_pinned,asset_class,symbol,timeframe,last_message_at,created_at').is('archived_at', null).order('is_pinned', { ascending: false }).order('last_message_at', { ascending: false, nullsFirst: false })` |
| Create chat | `from('chats').insert({ user_id, workspace, title: 'New chat', asset_class, symbol, timeframe }).select().single()` |
| Rename / archive | `from('chats').update({ title })` / `update({ archived_at: new Date().toISOString() })` `.eq('id', chatId)` |
| Delete chat | `from('chats').delete().eq('id', chatId)`. Allowed for `kind = 'standard'` only; messages cascade |
| Save composer context | `from('chats').update({ asset_class, symbol, timeframe }).eq('id', chatId)` |
| Load messages | `from('messages').select('*').eq('chat_id', chatId).order('created_at', { ascending: true }).limit(200)` |
| Realtime replies | `channel('chat:'+chatId).on('postgres_changes', { event: 'INSERT', schema: 'public', table: 'messages', filter: 'chat_id=eq.'+chatId }, handler).subscribe()` |
| Holdings CRUD | `from('holdings')` select / insert / update / delete (own rows) |
| Profile | `from('profiles').select('*').single()`; update `display_name, base_currency, risk_profile, timezone` |
| Artifacts | `from('artifacts').select('id,workspace,kind,title,chat_id,created_at').order('created_at', { ascending: false })`; read one with `content_md`; delete |
| Snapshot history (P2) | `from('portfolio_snapshots').select('as_of,total_value,health_score').order('as_of', { ascending: false }).limit(30)` |

The browser **never** inserts assistant messages, agent runs, artifacts or snapshots. RLS forbids it.

## 3. Browser ↔ Next.js API routes

Every route requires a Supabase session cookie (server client). Without one it returns `401 UNAUTHORIZED`.

### 3.1 `POST /api/chat/send`

Request:

```json
{
  "chat_id": "0b6c2f7e-…",
  "text": "Where are the key levels today?",
  "context": { "asset_class": "crypto", "symbol": "BTCUSDT", "timeframe": "1h" },
  "mode": "chat",
  "retry_request_id": null
}
```

| Field | Rule |
|---|---|
| `chat_id` | Required; must be the caller's chat (load through RLS, otherwise 404) |
| `text` | 1–8,000 characters after trim. Ignored on retry |
| `context` | Optional; validated against `ChatContext` |
| `mode` | `chat` (default) or `portfolio_review`. `portfolio_review` is only allowed in a `portfolio` chat |
| `retry_request_id` | Set on retry. The route reuses the existing user message with that `request_id` instead of inserting a new one |

Behaviour:

1. Validate the request and load the chat. This gives the route the `workspace`.
2. Unless this is a retry: `request_id = crypto.randomUUID()`. Insert the user message `{ chat_id, user_id, role: 'user', content: text, request_id, context: { ...context, mode } }`.
3. If the composer context changed, update `chats.asset_class/symbol/timeframe`.
4. `POST` to n8n `/aura/v1/chat/message` (§4.1) with a 10 s timeout.
5. Respond:
   - **202** `{ "request_id": "…", "message": <messages row> }` on success or duplicate;
   - **502** `AGENT_UNAVAILABLE` with `details: { "request_id": "…", "message": <row> }` if n8n failed. The UI shows "Not delivered" and a Retry button.
6. Rate limit: 10 sends per minute per user, otherwise `429 RATE_LIMITED`.

### 3.2 `GET /api/market/overview`

This route is served by Next.js directly, not by n8n (see [04-data-sources.md §5](04-data-sources.md#5-nextjs-direct-calls-ui-only)).

### 3.3 `GET /api/market/candles?symbol=BTCUSDT&asset_class=crypto&timeframe=1h&limit=300`

### 3.4 `GET /api/portfolio/snapshot`

This route proxies to n8n `/aura/v1/portfolio/snapshot` (§4.2), passing `user_id` from the session. It is cached per user for 60 s, and `?fresh=1` bypasses the cache (the Refresh button). The response is `PortfolioSnapshot` (§5).

## 4. Next.js ↔ n8n webhooks

- Base URL: `N8N_WEBHOOK_BASE_URL` (for example `https://<instance>.app.n8n.cloud/webhook`).
- Headers: `X-Aura-Key: <N8N_WEBHOOK_KEY>`, `Content-Type: application/json`.
- n8n validates the key with the Header Auth credential **"Aura Webhook Key"**.

### 4.1 `POST /aura/v1/chat/message`: the gateway

Request:

```json
{
  "request_id": "6f1c0e8a-…",
  "user_id": "a3d1…",
  "chat_id": "0b6c2f7e-…",
  "message_id": "9e77…",
  "workspace": "trading",
  "mode": "chat",
  "context": { "asset_class": "crypto", "symbol": "BTCUSDT", "timeframe": "1h" },
  "client": { "timezone": "Europe/Berlin", "sent_at": "2026-10-07T12:04:00Z" }
}
```

The message text is **not** sent. The gateway reads it from `messages` by `message_id` and checks that `chat_id` and `user_id` match. `daily_review` runs are started internally by the scheduled job, not through this webhook.

Responses (returned immediately, before any agent work):

| Status | Body | When |
|---|---|---|
| 202 | `{ "accepted": true, "request_id": "…", "duplicate": false }` | New request accepted |
| 200 | `{ "accepted": true, "request_id": "…", "duplicate": true }` | A run for this `request_id` already exists |
| 400 | error `VALIDATION_ERROR` | Missing or invalid fields |
| 401/403 | (n8n default) | Bad or missing `X-Aura-Key` |

**What the gateway guarantees** after a 202:

1. It writes **exactly one** assistant message for the `request_id`: success, refusal or error.
2. The `agent_runs` row moves `running` → `completed` | `refused` | `failed`, with `latency_ms`, `model` and token usage when available.
3. That message is written within 150 s. If not, it writes the `AGENT_TIMEOUT` error message.
4. If the agent returned an `artifact`, the gateway inserts it into `artifacts` first and sets `metadata.artifact_id`.
5. If the chat title is still `New chat` and the agent returned `title_suggestion`, it updates `chats.title`.
6. It checks the monthly cap (see [06-database.md](06-database.md) `monthly_usage`) before running the agent. Over the cap, it writes `BUDGET_EXCEEDED`. The cap is disabled in Phase A (`cap = null`).

### 4.2 `GET /aura/v1/portfolio/snapshot?user_id=<uuid>`

The response is `200` with a `PortfolioSnapshot` (§5). A user with no holdings gets `positions: []`, `total_value: 0` and `health: null`. A missing `user_id` gets `400`.

## 5. Portfolio snapshot payload

```ts
export interface PortfolioPosition {
  holding_id: string;
  asset_class: AssetClass;
  symbol: string;              // holdings symbol (BTC, NVDA, XAU, USD)
  display_name: string | null;
  quantity: number;
  price: number | null;        // in base currency
  value: number | null;        // quantity × price
  weight: number | null;       // value / total_value
  avg_cost: number | null;
  pnl_pct: number | null;      // (price − avg_cost) / avg_cost × 100
  change_24h_pct: number | null;
  price_source: string | null;
  price_as_of: string | null;
}
export interface HealthFlag { code: string; message: string; severity: 'info' | 'warning' | 'critical' }
export interface PortfolioHealth {
  score: number;               // 0–100, deterministic (agents/portfolio/SPEC.md §5)
  label: 'healthy' | 'watch' | 'at_risk';   // ≥80 / 60–79 / <60
  components: { diversification: number; class_balance: number; liquidity: number; data_quality: number }; // max 40/35/15/10
  flags: HealthFlag[];
}
export interface PortfolioSnapshot {
  as_of: string;
  base_currency: string;
  total_value: number;
  total_cost: number | null;
  pnl_abs: number | null;
  pnl_pct: number | null;
  day_change_abs: number | null;
  day_change_pct: number | null;
  allocation: Array<{ asset_class: AssetClass; value: number; weight: number }>;
  positions: PortfolioPosition[];
  missing_prices: string[];
  health: PortfolioHealth | null;
}
```

## 6. Gateway ↔ agent sub-workflows (Execute Workflow)

Each agent workflow starts with an **Execute Workflow Trigger** whose input fields are defined explicitly as the fields of `AgentInput`. Its last node returns **one item** shaped as `AgentOutput`.

```ts
export interface AgentInput {
  request_id: string;
  user_id: string;
  chat_id: string;
  workspace: Workspace;
  mode: AgentMode;
  message: string;             // user message text from DB; for daily_review the job supplies an instruction
  context: ChatContext;        // from the user message (falls back to the chat's saved context)
  history: Array<{ role: MessageRole; content: string; created_at: string }>; // oldest → newest, max 20, current message excluded
  profile: { display_name: string; base_currency: string; risk_profile: RiskProfile; timezone: string };
  now: string;                 // ISO UTC, set by the gateway
}

export interface AgentOutput {
  reply_md: string;            // markdown shown to the user
  on_topic: boolean;           // false only for the guardrail refusal
  title_suggestion: string | null;          // 3–6 words, only when history is empty
  suggested_workspace: Workspace | null;    // set when another workspace fits better
  chart: ChartRef | null;      // set when the answer is about one tradable symbol's price action
  sources: SourceRef[];        // every dataset used
  artifact: { title: string; kind: ArtifactKind; content_md: string } | null;
  model: string | null;        // filled by the "Normalize output" node
  usage: { input_tokens: number | null; output_tokens: number | null } | null;
}
```

## 7. Tool result envelope (n8n tool sub-workflows)

Every `Aura · Tool · *` workflow returns **one item**:

```json
{ "ok": true, "source": "binance", "as_of": "2026-10-07T12:04:00Z", "data": { } }
```

or, without throwing:

```json
{ "ok": false, "error": { "code": "UPSTREAM_ERROR", "message": "Binance futures returned 451; Bybit fallback also failed", "provider": "binance-futures" } }
```

Tool-specific inputs and `data` shapes are defined in each agent's `SPEC.md`.
